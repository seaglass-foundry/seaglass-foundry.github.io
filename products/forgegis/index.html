The benchmark

The benchmark of record, run 20261004-094534-191f1b44: ForgeGIS 1.2.6 against GDAL 3.12, warm timings, the median of each timed block. This is the benchmark; the race further down is a separate demonstration.

  • 15× geomean
    geometric-mean speedup over GDAL 3.12 across 242 operations with a GDAL equivalent and both sides timed, no category excluded, at sizes from 16×16 to 8192×8192 pixels. ForgeGIS was faster in 239 of 242; the 3 slower were all tiny: raster creation and rasterize at 256×256, and raster creation at 1024×1024.
  • 6× kernel
    kernel against kernel: GDAL in process, on operations where both sides take at least 1 ms, 256×256 to 4096×4096 and real elevation tiles. Sub-millisecond work is where timer resolution dominates, so this is the figure to lead with where precision matters.
  • Parity
    1191 checks pass, 0 fail. 884 compare ForgeGIS’s output with GDAL’s or an independent oracle within a tolerance stated per operation; 294 are consistency checks that do not count as parity evidence, and 13 are smoke checks only. Every output was also re-run and compared for determinism.
  • By category
    faster in every category measured (geometric mean): pipelines 81×, resampling 30×, transforms 30×, vectorizing 26×, warps 24×, zonal and focal 20×, terrain 4.3×, viewshed 3.4×, raster I/O 3.0×.
  • 178× workflow
    against the GDAL command line, including process start, on the 30 operations where GDAL runs as a command-line tool: a workflow cost, not a kernel cost.

Method

  • GDAL 3.12.1 in process through its Java bindings; command-line pipelines use GDAL 3.11.5, the version those tools report.
  • Timing protocol v4: warm runs, the median of each block, with the GPU kept in its working state between timed blocks, as a sustained workload would see it.
  • The geometric mean covers every GDAL-referenced operation with both sides timed, no category excluded, sub-millisecond rows included.
  • “Warm” means after the operation has run once; the first call after the GPU has gone idle costs more, and can be slower than GDAL for sub-millisecond work.
  • The timing method was tightened in this release, so earlier published figures are not directly comparable.

Performance demonstration

Not the benchmark: a race you can watch. 61 operations on real terrain — Copernicus elevation over the Grand Canyon, the Alps and UTM zone 33N, and a 6-band Sentinel-2 scene — run side by side with GDAL, each operation once on each side. One take, in real time, with no cuts.

How the race runs

  • Inputs are loaded before the timers start, for both: ForgeGIS’s onto the GPU, and GDAL’s into an in-memory dataset. Each timer covers the operation and reading the result back.
  • Single operations call GDAL through its Java bindings, in memory. Multi-stage pipelines run as GDAL command-line chains that write each stage to disk, the way those chains run in practice.
  • Each operation runs once on each side, ForgeGIS first, with ForgeGIS kernels compiled during warmup — so the race shows single runs, not the warm medians of the benchmark above.
